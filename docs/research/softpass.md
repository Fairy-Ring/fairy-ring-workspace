# Soft-pass ledger — process stage, not failure

**Purpose:** Track **mid-gate soft entry** and labeled thrash while product is wired.  
**Not:** a shame list. Soft-pass is a **stage of the process**.

## Why soft-pass exists

Implementing a quest/skill mid-gate still requires real work even when the host soft-sets an entry stage:

| Still real | Soft may skip (for now) |
|------------|-------------------------|
| Varp / varbit / multi bits **ids** and names | Authentic commute to that stage |
| Content that **reads** those vars (dialogue, loc ops, IF) | Full 0→N product path |
| Client display of stage (quest list, overlays) | Optional combat floors already thrash-proven elsewhere |
| Pack params that drive next stage | Dep quests not yet residual-hard |

A soft mid that **product-writes** the next stage is progress. It is **not** residual e2e complete, and it is **not** an intentional period deviation (those live in [`deviations.md`](deviations.md)).

## Claim classes (same vocabulary as promise bar)

| Label | Meaning |
|-------|---------|
| **SOFT mid** | Host entry once (or labeled prep) + product under test |
| **SEG** | Soft entry **N once** → residual **N→target** under bar §2 (no further progress cheats) |
| **HARD** | Continuous product path; stages written by content with only allowed prep |
| **Superseded** | Older thrash replaced by a better run — leave row for archaeology |

**Misclaim (still wrong):** logging soft `setvar` of the *claimed* stage as residual **PASS**, or soft-greening without a row here.

## Process ladder (use all three)

```text
1. Config / varp / script unit → pack
2. Soft mid (this ledger) → prove stage N drives client + content correctly
3. Residual / HARD e2e → no progress cheats for the claimed span
```
